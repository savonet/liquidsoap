# Build: dune and OCaml toolchain notes (Part B)

How the current tree implements [../build.md](../build.md). File references
are relative to the ffmpeg root.

## Project file (`dune-project`)

- `(lang dune 3.23)`, `(generate_opam_files true)`,
  `(opam_file_location inside_opam_directory)` (opam files and their
  `.opam.template` companions live in `opam/`), `(subst disabled)`.
- `(use_standard_c_and_cxx_flags false)`.
- Every package has `(allow_empty)`. This is what makes a disabled library
  a legal (empty) package, and why the install-time check exists.
- When embedded, the nested `dune-project` makes this directory its own
  dune project inside the liquidsoap workspace; its packages are visible
  workspace-wide. `/dune-workspace` of the enclosing repository sets
  `LIQUIDSOAP_INSTALL_NO_OPTIONAL_FAIL=true` through `(env (_ (env-vars …)))`
  on the default context.

## Library stanzas (`<lib>/dune`)

All seven follow one template:

```
(library
 (name <lib>) (public_name ffmpeg-<lib>)
 (enabled_if (= %{read:../detect/<lib>_available} "true"))
 (foreign_stubs (language c) (names <lib>_stubs)
  (flags (:include ../detect/<lib>_c_flags.sexp)))
 (c_library_flags (:include ../detect/<lib>_c_library_flags.sexp))
 (libraries …))
```

- `enabled_if` with `%{read:…}` compares the whole file content, which is
  why `detect` writes `true`/`false` with no trailing newline.
- `(flags (:include …))` has no `:standard`: the stanza's C flags are only
  the pkg-config cflags and the four warning flags. The compiler driver
  still adds the OCaml configuration's own flags. Observed compile command
  for `avutil_stubs.o` (`dune rules`):
  `gcc -O2 -fno-strict-aliasing -fwrapv -fPIC -pthread -D_FILE_OFFSET_BITS=64 -I<ffmpeg>/include -Wall -Wextra -Werror=unused-variable -Werror=unused-parameter -g -I <ocaml> -I <ocaml>/threads -I <ocaml>/unix -o avutil_stubs.o -c avutil_stubs.c`.
- `:include` needs an s-expression file, hence the `.sexp` outputs;
  `%{read-lines:…}` (used to pass flags to `gen_code.exe` as separate
  arguments) needs one flag per line, hence the second, plain file.
- `install_c_headers` lists header base names without `.h`:
  `avutil/dune:25-28`, `avcodec/dune:25`, `av/dune:25`. Generated headers
  can be listed (two of avutil's three are generated).
- Sibling stubs find each other's headers (`avutil_stubs.h`,
  `avcodec_stubs.h`, `av_stubs.h`, `media_types_stubs.h`,
  `polymorphic_variant_values_stubs.h`) because dune adds an include
  directory for every library in `(libraries …)` when compiling foreign
  stubs. No `(include_dirs …)` appears anywhere.
- Only `ffmpeg/dune` uses `(optional)`. The seven binding libraries use
  `enabled_if` alone.

## Install check (`<lib>/dune:1-10`)

```
(rule (alias install) (package ffmpeg-<lib>)
 (enabled_if (not (= %{env:LIQUIDSOAP_INSTALL_NO_OPTIONAL_FAIL=false} true)))
 (action (with-stdin-from ../detect/<lib>_available
          (run ../detect/check.exe <lib>))))
```

A rule with no target attached to the `install` alias and scoped to a
package: it runs under `dune build -p ffmpeg-<lib> @install`, the opam
build command. `detect/check.ml` reads stdin with `input_line`, which
raises `End_of_file` on an empty file; the file is never empty in practice.

## Detection (`detect/`)

- `detect/dune` holds seven near-identical rules, one per library, each
  with four targets and `(deps (universe))`. The rule runs
  `../detect/detect.exe` from the `detect` directory, so outputs land
  there.
- `detect.ml` uses `Configurator.V1.create "ffmpeg-detect"` directly
  rather than `Configurator.V1.main`, so it parses its own arguments and
  does not need the `-ocamlc`-style arguments `main` expects. It calls
  `Pkg_config.get` then `Pkg_config.query_expr_err ~package ~expr`.
- `Unix.putenv` is used to forward the per-context variables to the
  pkg-config child process; this is the only reason `detect` links `unix`.
- `%{os_type}` and `%{context_name}` are dune variables for the target
  context; `Sys.os_type` would describe the build machine, which differs
  when cross-compiling to Windows.
- `detect/all_available.ml` and `detect/check.ml` are stdlib-only.

## Generator (`gen_code/`)

- `gen_code/dune`: an executable with one C foreign stub
  (`gen_code_stubs.c`) and libraries `unix` and `str`. The stub is
  `polymorphic_variant_string_to_c_value : string -> int64`, which wraps
  `caml_hash_variant(String_val(name))` in `caml_copy_int64`. The generator
  prints the result with `Int64.to_string`.
- `caml_hash_variant` returns the tagged immediate, sign-extended from 32
  bits, so that the same constant is valid on 32- and 64-bit targets. The
  generator runs on the build machine and its output is compiled for the
  target; this sign extension is what makes that safe.
- `config.ml` is generated by a rule in the same `dune` file:
  `(with-stdout-to config.ml (run ./config/discover.exe %{context_name}))`.
  The module is then an ordinary module of the `gen_code` executable
  (`Config.paths`).
- `gen_code/config/discover.ml` uses `Configurator.V1.main
~name:"ffmpeg-gen_code-pkg-config"`. `main` parses `Sys.argv` itself, so
  the program sets `Arg.current := 1` to make it skip the context-name
  argument (`discover.ml:66`). It uses `C.which` and `C.Process.run`, not
  `Pkg_config`. Paths are printed with `%S`.
- Regular expressions are `Str` regexps (`gen_code.ml:86-88`), matched
  with `Str.string_match … 0` (anchored at the start, not at the end).
  The member capture is `\\([A-Z0-9_]+\\)`. The stop pattern `\\};` is
  `Str` syntax for a literal `};`.
- The table list is data: `generators` (`gen_code.ml:408-618`), built with
  the `enum`, `flags` and `codec_id_range` helpers
  (`gen_code.ml:372-406`). Dispatch on `Sys.argv.(2)` is at
  `gen_code.ml:620-629`.
- The preprocessor is run with `Unix.open_process_in` on
  `Printf.sprintf "%s -E %s %s" cc c_flags (Filename.quote path)`
  (`gen_code.ml:220-231`). The exit status is checked by an `assert`, and
  the enclosing `try … with _` turns that assertion failure, like any
  other exception, into the plain-file fallback.
- Emission of both output kinds shares one traversal: the `h` mode passes
  only the header channel, the `ml` mode only the OCaml channel, and each
  print is a no-op for the absent channel (`if_d`, `gen_code.ml:23`).
- `%{cc}` is passed quoted (`"%{cc}"`) so the compiler and its
  configuration flags arrive as one argument.

## Generator rules in library `dune` files

One rule per output file, all of this shape:

```
(rule (targets <table>_stubs.h) (deps ../detect/<lib>_c_flags)
 (action (run ../gen_code/gen_code.exe "%{cc}" <table> h
          %{read-lines:../detect/<lib>_c_flags})))
```

- The FFmpeg headers themselves are not declared dependencies. A table is
  regenerated when the detected flags file changes, not when a header
  changes in place.
- Some `.ml` rules also list the matching `_stubs.h` as a dependency
  (`avutil/dune:65,87`, every `.ml` rule of `avcodec/dune`); the others do
  not. The generator does not read the header it supposedly depends on, so
  this only adds an ordering edge.
- Generated `.ml` files become modules of the library automatically
  because no `(modules …)` field restricts them.

## Fallback rules on the stub sources

`avutil/dune:31-50`, `avcodec/dune:28-37`, `swresample/dune:27-32`:

```
(rule (targets <lib>_stubs.c) (mode fallback)
 (deps <generated headers>) (action (echo "this should not happen")))
```

In fallback mode dune ignores a rule whose targets all exist in the source
tree, so this rule is inert. Were the source missing, the action would not
create the target and the build would fail. The header-before-stub ordering
does not come from it: `dune rules avutil/avutil_stubs.o` shows the object
depending on every `.h` of the directory, including `media_types_stubs.h`,
which the stub does not include. The avutil list names
`media_types_stubs.h` although the avutil stub does not include it; the
avcodec list omits `media_types_stubs.h`, which the avcodec stub does
include (it comes from the avutil library's directory).

## Generated C: what the stubs rely on

- Table rows are `int64_t`; `value` and the C enum are compared to them
  after implicit conversion (`v==TAB[i][0]`, `(int64_t)t==TAB[i][1]`).
- `Fail(...)` is the macro from `avutil/avutil_stubs.h:33-38`: it formats
  into a shared static buffer and calls the OCaml closure registered as
  `ffmpeg_exn_failure`. The `return -1;` after it is unreachable.
- Functions in generated headers are defined, not declared, with external
  linkage; the header has no guard. One translation unit per program may
  include a given generated header.
- `VALUE_NOT_FOUND` is redefined identically by every generated header.

## Tests and examples

- `gen/dune` builds `gen_test.exe` and `gen_examples.exe` and stores their
  output with `(with-stdout-to …)`; the argument is
  `%{read:../detect/all_libs_available}`.
- `test/dune` and `examples/dune` pull the result in with
  `(dynamic_include ../gen/<…>.inc)`: the included file is itself a build
  product, which plain `(include …)` does not allow.
- `gen_test.ml` emits `(executables (names …) (modules … test_assert))`
  because dune rejects a module claimed by several stanzas.
- The `ffmpeg_citest` rule uses named dependencies (`(:runner
test_runner.exe)` …) and a `(progn …)` action; it has `(package ffmpeg)`.
- `examples/dune` sets `(env (dev (flags (:standard -warn-error -A))))`.
- `test/test_runner.ml` uses `Unix.create_process` and `Unix.waitpid`.

## Top-level summary rule (`dune`)

`(mode (promote (only ffmpeg.config) (until-clean)))` with a `progn` of
`echo` actions followed by `(with-stdout-to %{target} (echo ""))`. The
`echo` actions outside `with-stdout-to` write to dune's own output.
`ffmpeg.config` is listed in `.gitignore`.
