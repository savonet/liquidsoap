# Conformance

Part A. The checks a writer, a sink and an output that drives them are run
against, grouped by principle, and the doubles a harness needs. This file
owns the grouping, the marks and the "failed before" record. Each check's
scenario is owned by the Tests section of the file named in its "Source"
column (an implementation file's §16, a caller file's §10, a contract
file's conformance section). The rule each check enforces is the one
linked in its "Rule" column; it is not restated here.

It relies on: [testing.md](../../../spec/testing.md), which every check
below follows (a pass must be able to say no, a suite asserts that it ran,
a skip is never a pass, audio compared by sample with two frame sizes); the
contract ([encoder.md](encoder.md), [formats.md](formats.md),
[sink.md](sink.md), [shared-stream.md](../../outputs/spec/shared-stream.md));
the conformance files of the neighbouring trees, linked where a caller
answers through them.

## Marks and columns

- **Binding**: what the check asserts. Everything else it observes (log
  wording, timing within the stated tolerance, the order of independent
  events) is incidental ([testing.md §2](../../../spec/testing.md#2-binding-and-incidental)).
- **K**: the check is the "How to tell" of an entry of
  [known-complexity.md](known-complexity.md), named in the column.
- **S**: the check verifies a script-visible behaviour the tree binds with
  a migration note: a refusal at evaluation that a script written for the
  previous behaviour meets, or a delivery an existing deployment observes
  (final bytes to a server, one logical stream where a chain was).
- **Failed before**: `yes` with the finding id when a confirmed defect of
  the findings of the as-built snapshot (commit 2e6bab6a5, `findings/`, the verification files governing) makes
  the previous implementation fail the check; `—` when no confirmed defect
  is recorded, which says nothing either way. A `yes` is the check's
  positive control: it counts once it has been seen failing against that
  build ([testing.md §1](../../../spec/testing.md#1-a-pass-must-be-able-to-say-no)).
