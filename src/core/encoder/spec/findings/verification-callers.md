## Confirmed defects, ranked

Data loss first, then correctness, then cosmetics.

1. **ffmpeg V1**: `%ffmpeg`'s `header ()` is empty for any codec with an encoder delay (AAC, LAME MP3). Every shared `output.harbor` listener and every late `output.srt` peer of such a stream gets an undecodable stream (no container header). Cause in the bindings and the encoder (`av_stubs.c:1887`, `instance.ml:230-279`), not in harbor.
2. **ffmpeg F1**: a format that needs a seekable destination (MP4, MOV) on any `Stream` caller or `output.file(append=true)` streams nothing, forever, with one log line and no error.
3. **file-callers 1**: pipe outputs never record metadata: `$(…)` in file names and commands interpolates to empty strings. With a per-track name, every track goes to the same file and truncates the one before.
4. **ffmpeg F4**: `output.url` to a plain path with `truncate=0` overwrites from offset 0 without truncating (corrupt file); a plain path also drops Ogg metadata where `file:` chains.
5. **ffmpeg F2**: an Ogg `%ffmpeg` file with a protocol option fails at the first metadata change and stops the output (the script, with the default `reopen_on_error`).
6. **net-callers D5**: `output.icecast` throws away the encoder's final bytes on every disconnection (about 1.4 s of Vorbis here, and no EOS page).
7. **file-callers 2**: a failed open pins the file name; the output retries the same file forever.
8. **file-callers 4**: after a restart, `pipe` declares the process's output rate in the header it writes, so the audio is read at the wrong rate.
9. **file-callers 5** (worse than reported): `pipe` compares a byte offset with a track-mark position. Mid-frame track marks are mishandled at default rates, and the process restarts twice.
10. **net-callers D3**: Icecast drops the first piece of every connection.
11. **ffmpeg F5**: the `opus`, `oga`, `ogv` and `spx` muxers never chain, so metadata changes are dropped.
12. **ffmpeg F3**: an unknown muxer name is silently replaced by the file extension's muxer.
13. **ffmpeg F9**: non-FFmpeg exceptions leave the instance `Started`, and a failed restart leaves a closed container current (latent).
14. **net-callers D1**: non-chunked `Cry.send` writes the wrong range for views with offset ≠ 0 (latent).
15. **net-callers D2**: `%ffmpeg` never announces its bitrate to Icecast.
16. **net-callers D4**: the Icecast retry delay is rounded up to the next whole second.
17. **ffmpeg F6**: leftover options are reported one layer at a time.
18. **file-callers 3**: `output.external` is logged and named `output.file`, because `set_id ~force:false` never sets anything.
19. **file-callers 6**: cover art reaches pipe encoders by default, and `coverart` even with `export_cover_metadata=false`. This conflicts with output.md §3.
20. **file-callers 7** (partly): the pipe outputs' reset is a no-op. output-file.md documents it, but output.md §4 does not allow it.
21. **ffmpeg F7, F8**: the FFmpeg encoder spec's seek callback, factory signature and `output.url` row do not match the code.

## Refuted

None outright. Corrected in part: F1 (where the failing write happens), file-callers 3 (`name` is never applied to any output), file-callers 5 (wrong at default rates too) and file-callers 7 (the no-op reset is documented in output-file.md).
